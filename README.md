## 3) 분석 방법 (실제로 한 일 10단계)

> 아래는 초안입니다. **실제로 한 일에 맞게 수정**하세요.

| 단계 | 무엇을 | 어떻게 | 왜 |
|---|---|---|---|
| 1. 데이터 수집 | 활동·수면 파일 확보 | kagglehub로 다운로드, 폴더 구조와 열 이름 확인 | 필요한 열이 있는지 먼저 확인 |
| 2. 변수 선택 | 입력과 목표 정하기 | 입력: 고강도·중강도·저강도·좌식 시간, 걸음 수 / 목표: 수면 부족 여부(수면 [360]분 미만) 또는 수면 효율 | 질문과 직접 관련된 변수만 사용 |
| 3. 전처리 | 중복·미착용일·낮잠 제거 | 중복 삭제, 걸음 0이고 좌식 1440분인 날 제외, 수면 [180]분 미만 제외 | 미착용·부분 기록이 결과를 왜곡하지 않게 |
| 4. 분할 | 학습/검증 나누기 | 사용자 단위 분할(GroupKFold [ ]겹) | 같은 사람의 여러 날이 양쪽에 섞이면 성능이 부풀므로 |
| 5. 기준선 | 아무것도 안 하는 모델 | 다수 클래스 예측(분류), 평균 예측(회귀) | 모델이 의미 있는지 비교할 바닥선 |
| 6. 후보 모델 비교 | 여러 모델 학습 | 로지스틱, 결정트리, 랜덤포레스트 (+회귀 모델) | 한 모델만으로는 "최선"이라 말할 수 없어서 |
| 7. 선택 | 최상의 모델 고르기 | 교차검증 점수와 분할별 편차 비교 | 점수뿐 아니라 흔들림도 봐야 해서 |
| 8. 평가 | 선택 모델 점검 | 균형 정확도·재현율·정밀도·F1·혼동행렬 / 회귀는 MAE·R² | 클래스가 한쪽에 몰릴 때 정확도의 착시를 피하려고 |
| 9. 해석 | 왜 그 모델이 나았는지 | 변수 넣고 빼기 실험, 오분류 사례, 사용자별 결과 | 점수보다 이유가 핵심 |
| 10. 한계 점검 | 한계 정리 | 같은 날 매칭, 수면 부족 기준을 [300·420]분으로 바꿔 결론 확인 | 과한 일반화 방지 |

**수면 부족 기준:** 수면 [360]분 미만. 연구자가 정한 값이며 임상 진단이 아닙니다. 이 기준을 택한 이유: [직접 작성]
